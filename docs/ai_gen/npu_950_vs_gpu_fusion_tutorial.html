5. 融合性能维度比例之外:融合了也不一定像 GPU 那样赚

GPU:融合几乎单调有益 省 kernel launch + 省 DRAM 往返 中间值住寄存器,融合加深几乎免费 规约可铺满整机(split reduction)
收益公式:省掉的 DRAM 往返 > 0 → 融合
A5:三要素全部弱于 GPU 同构融合 并行度:tile 搜索被核数钳制(wave 量化 0.72);规约单核(H3) 驻留与流水:tile 驻留小 → 循环深;multibuffer 深度受 UB 限制 跨单元协调:含 GEMM 的融合走 CV 流水,有调度/同步开销
且 L2 192MB 稀释"省 DRAM"收益;大 kernel 还有运行时错误风险

决策质量:默认不实测融合收益

  • benchmark_fusion 默认关(与上游一致):大多数 pointwise/reduction 融合不实测收益,赌启发式正确;A5 仅对固定 tile 模板 epilogue 做编译验证。
  • 开启 benchmark 时,A5 用 profiler 批测 + L2 flush(scheduler.py:37-219;批次 TOTAL_STEP=10,注释写 50 与实现不一致)替代事件计时——计时口径系统性不同于 GPU。
  • 判死更严:spill>0 即 inf(上游 >8)、nolinear 拆不开静默 inf——宁可错杀,压比例也改变"哪些融合活下来"的分布。

7. 定量诊断:三桶归因法① : ②③ 的量级 ≈ 软件 : 硬件

  • 桶① 不在融合池(纯软件):统计 wrapper 输出中 aclnn 调用数 / 总节点数,即 fallback/extern 占比。边界对照:NPU_INDUCTOR_FALLBACK_LIST=allfallback(全 fallback,融合归零)。
